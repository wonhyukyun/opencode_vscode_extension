## 1. 개요

OpenCode는 오픈소스 AI 코딩 에이전트입니다. 기본 형태는 CLI(명령줄 인터페이스)와 TUI(터미널 UI)여서, 사용하려면 별도 설치와 터미널 조작이 필요합니다. OpenCode Integrated는 이 진입 장벽을 없애기 위해 만든 VS Code 확장입니다. 민간 오픈소스 에이전트를 그대로 활용하되, 설치·실행·운용을 VS Code 안에서 끝내도록 통합했습니다. [확인필요: 국방 융합 관점의 개발 배경]

핵심 접근 방식은 "엔진 동봉"입니다. 확장 패키지(VSIX)에 플랫폼별 OpenCode 실행 파일을 포함하고, 확장이 활성화될 때 루프백 주소(`127.0.0.1`)의 임시 포트로 숨김 서버를 띄웁니다. 서버는 실행마다 새로 생성한 무작위 비밀번호로 Basic 인증을 요구하므로 같은 PC의 다른 프로세스가 접근하기 어렵습니다. 채팅 화면은 CSP(Content Security Policy)를 적용한 웹뷰이며, 파일 접근과 비밀 정보는 확장 호스트에만 둡니다.

기대 효과는 두 가지입니다. 첫째, 사용자는 `opencode` CLI를 설치하거나 터미널을 열 필요가 없습니다. 둘째, 각 VSIX가 하나의 실행 파일만 포함하므로 패키지가 자기완결적이고 배포 단위가 명확합니다. 코드 리뷰, 리팩토링, 문서 작성 등 편집기 안에서 AI 에이전트를 쓰는 모든 시나리오에 적용할 수 있습니다.

## 2. 주요 기능

- **내장 엔진 자동 관리** — 사이드바를 열면 엔진이 자동으로 시작하고, VS Code 종료 시 함께 종료됩니다. 사용자는 서버 기동을 신경 쓸 필요가 없습니다.
- **스트리밍 채팅과 세션 관리** — 응답이 실시간으로 표시되고, 워크스페이스별 세션(대화) 목록에서 새 대화 생성·전환·삭제가 가능합니다.
- **모델·사고 강도·에이전트 선택** — OpenCode 설정에 등록된 제공자·모델 중 하나를 고르고, 모델이 지원하면 사고 강도(effort)와 에이전트를 함께 지정합니다.
- **편집기 컨텍스트 첨부** — 현재 파일이나 선택 영역을 한 번의 명령으로 대화에 붙입니다. 줄 번호 정보가 함께 전달됩니다.
- **`@파일` 및 이미지 첨부** — 입력창에서 `@`로 워크스페이스 파일을 검색해 첨부하고, 이미지는 붙여넣기·드래그·버튼으로 추가합니다.
- **`/명령` 실행** — OpenCode에 정의된 명령과 스킬을 `/`로 호출합니다. 내장 명령 `/new`, `/clear`, `/help`를 제공합니다.
- **도구 권한 제어** — 에이전트가 파일 편집이나 셸 명령을 요청하면 입력창 위에 승인 요청이 표시됩니다. 권한 모드 4종(Manual, Edit automatically, Plan, Auto)으로 기본 정책을 정합니다.
- **질문 응답과 사용량 표시** — 에이전트의 선택형 질문에 패널에서 답하고, 현재 컨텍스트·세션 누적 토큰과 컨텍스트 창 잔여량을 확인합니다.

## 3. 스크린샷 / 아키텍처

- [이미지: 사이드바 채팅 전체 화면] 캡션: "OpenCode 사이드바. 상단 세션 목록, 중앙 메시지, 하단 입력창과 모델·권한 모드 선택"
- [이미지: 권한 요청 카드] 캡션: "도구 권한 요청. Deny / Always allow / Allow once 세 가지로 응답"
- [이미지: `@` 파일 검색 제안 목록] 캡션: "입력창에서 @ 입력 시 워크스페이스 파일 검색"
- [이미지: 아키텍처 다이어그램] 캡션: "확장 호스트가 내장 엔진을 기동하고 HTTP/SSE로 통신, 웹뷰는 postMessage로만 확장 호스트와 통신"

아키텍처는 세 부분으로 구성됩니다. 확장 호스트(`extension.ts`, `server.ts`, `chatView.ts`, `client.ts`)는 엔진 프로세스를 `serve --hostname 127.0.0.1 --port <임시포트>`로 실행하고 `/global/health`가 응답할 때까지 최대 20초 대기합니다. 이후 OpenCode 로컬 HTTP API로 세션·메시지·모델·권한·질문을 처리하고, `/event` SSE(Server-Sent Events) 스트림을 구독해 실시간 변화를 받습니다. 웹뷰(`webview/main.ts`)는 확장 호스트와 메시지만 주고받으며 마크다운을 `marked`와 `DOMPurify`로 렌더링합니다.
