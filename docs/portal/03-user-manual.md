## 1. 시작하기

1. VS Code에서 작업할 폴더를 엽니다.
2. `Ctrl+Esc`를 누르거나 활동 표시줄의 OpenCode 아이콘을 선택합니다.
3. "Starting OpenCode…" 표시가 사라지고 입력창이 활성화될 때까지 기다립니다.

화면 구성은 위에서 아래로 다음과 같습니다. [캡처: 사이드바 전체 화면, 각 영역에 번호 표시]

| 영역 | 내용 |
|---|---|
| 상단 도구 모음 | 세션(대화) 선택 상자, 새 채팅(+) 버튼, 채팅 삭제 버튼 |
| 알림·질문 | 오류 알림과 에이전트의 선택형 질문 |
| 메시지 | 사용자·어시스턴트 메시지, 도구 활동 |
| 권한 요청 | 파일 편집·셸 명령 등 도구 승인 카드 |
| 입력창 | 컨텍스트 칩, 첨부 목록, 텍스트 입력, 전송(↑)·중지(■) 버튼 |
| 입력창 하단 | 권한 모드, 에이전트, 모델, 사고 강도 선택 상자, Image 버튼, 토큰 사용량, 상태 |

왼쪽 사이드바는 위에서부터 History, Skills, MCP Servers 세 칸으로 나뉩니다. 각 칸의 제목 막대를 눌러 접고 펼 수 있습니다.

### 1.1 Skills 칸

지금 엔진이 읽어 들인 스킬 목록입니다. 제목 옆에 전체 개수와 그중 내장 스킬 수가 표시됩니다. 디스크에서 온 스킬은 어느 폴더에서 왔는지가 오른쪽에 나오고, 항목을 누르면 해당 `SKILL.md` 파일이 편집기에서 열립니다. 엔진에 내장된 스킬은 다른 아이콘으로 구분되고 열 파일이 없습니다. 항목에 마우스를 올리면 설명 전문과 파일 경로가 보입니다.

### 1.2 MCP Servers 칸

`opencode.json`의 `mcp` 항목에 설정한 서버와 연결 상태입니다. 문제가 있는 서버가 항상 위로 올라옵니다. 상태는 Connected, Disabled, Needs authentication, Needs client registration, Failed 다섯 가지이며, 실패한 서버는 마우스를 올리면 엔진이 보고한 오류 메시지가 보입니다. 제목 옆에는 상태별 개수 요약이 표시됩니다.

두 칸 모두 엔진이 시작할 때 읽은 내용을 보여 줍니다. 스킬 파일이나 `opencode.json`을 고쳤다면 OpenCode를 다시 시작해야 반영됩니다. 목록만 다시 받고 싶으면 칸 제목 막대의 새로 고침 버튼을 누릅니다.

기본 단축키는 다음과 같습니다.

| 동작 | Windows | macOS |
|---|---|---|
| 사이드바 열기 | `Ctrl+Esc` | `Cmd+Esc` |
| 새 채팅 | `Ctrl+Shift+Esc` | `Cmd+Shift+Esc` |
| 메시지 전송 | `Enter` | `Enter` |

## 2. 핵심 기능 사용법

### 2.1 메시지 보내기

코드 질문, 수정 요청 등 모든 대화의 기본 동작입니다.

1. 입력창에 요청을 입력합니다.
2. `Enter`를 누르거나 전송(↑) 버튼을 선택합니다.
3. 응답이 스트리밍으로 표시됩니다. 중간에 멈추려면 중지(■) 버튼을 선택합니다.

결과 확인: 메시지 영역에 어시스턴트 응답과 도구 활동이 순서대로 나타납니다. 활성 세션이 없으면 자동으로 새 세션이 만들어집니다.

### 2.2 세션(대화) 관리

작업 주제별로 대화를 분리하고 싶을 때 사용합니다.

1. 새 대화는 새 채팅(+) 버튼 또는 `Ctrl+Shift+Esc`로 시작합니다.
2. 이전 대화는 상단 세션 선택 상자에서 고릅니다.
3. 삭제는 채팅 삭제 버튼을 선택하고 확인 대화상자에서 승인합니다.

결과 확인: 세션 목록은 현재 워크스페이스 기준으로 최대 50개까지 표시됩니다. 마지막으로 사용한 세션은 워크스페이스별로 기억됩니다. [캡처: 세션 선택 상자 펼친 화면]

History 패널은 대화를 레포지토리별로 묶어서 보여 줍니다. 현재 열려 있는 레포지토리가 항상 맨 위에 펼쳐진 상태로 오고, 아직 대화가 없어도 자리를 지킵니다. 나머지 레포지토리는 최근 활동 순서로 접힌 채 이어지며, 각 줄에는 그 레포지토리의 대화 수가 표시됩니다. 대화를 하위 폴더에서 시작했더라도 같은 레포지토리 묶음에 들어갑니다. 여러 대화를 한 번에 지우는 선택 모드는 레포지토리를 가로질러 동작합니다.

### 2.3 모델·사고 강도·에이전트 선택

작업 난이도나 비용에 맞춰 모델을 바꿀 때 사용합니다.

1. 입력창 하단 모델 선택 상자에서 `제공자/모델`을 고릅니다.
2. 모델이 사고 강도(effort) 옵션을 지원하면 오른쪽에 선택 상자가 나타납니다. `Default effort` 또는 원하는 값을 고릅니다.
3. OpenCode에 primary 에이전트가 등록돼 있으면 에이전트 선택 상자가 나타납니다. 필요 시 선택합니다.

결과 확인: 선택값은 다음 전송부터 적용되며 웹뷰 상태에 기억됩니다. 모델 목록이 비어 있으면 OpenCode 설정을 확인합니다(설치 가이드 3.3).

모델을 바꾸면 그 다음에 보내는 메시지부터 새 모델이 쓰입니다. 이미 전송한 요청은 바꾸기 전 모델로 끝납니다. 어시스턴트 답변마다 머리글 오른쪽에 그 답변을 만든 모델 이름이 표시되므로, 바뀐 모델이 실제로 쓰였는지 바로 확인할 수 있습니다.

0.3.1까지는 어떤 모델을 골라도 요청에 모델이 실리지 않아 항상 기본 모델이 답했습니다. 0.3.2에서 고쳤습니다. 이전 버전에서 저장된 모델 선호값은 처음 실행할 때 자동으로 새 형식으로 바뀝니다.

설정 `opencodeIntegrated.defaultModel`에 `제공자/모델` 형식으로 적어 두면 그 모델이 먼저 선택됩니다. 해당 에이전트에 아직 고른 모델이 없을 때 적용되며, 설정을 고치면 그 자리에서 반영됩니다. 없는 제공자나 모델을 적으면 조용히 무시하지 않고 무엇이 잘못됐는지 알림으로 알려 줍니다.

`/models` 또는 `/model`을 입력하면 모델 선택 상자가 열리고 현재 모델과 컨텍스트 창 크기가 상태 줄에 나타납니다.

### 2.4 편집기 컨텍스트 첨부

현재 보고 있는 코드에 대해 질문할 때 사용합니다.

1. 편집기에서 파일을 열거나 코드 범위를 선택합니다.
2. 편집기 우클릭 메뉴에서 **OpenCode: Add Selection to Chat**을 선택합니다. 또는 입력창 위 컨텍스트 칩을 선택해 켭니다.
3. 요청을 입력하고 전송합니다.

결과 확인: 컨텍스트 칩에 `경로#L시작-끝` 형식의 라벨이 표시됩니다. 선택 영역이 없으면 파일 전체가 참조로 첨부됩니다. 첨부는 한 번 전송하면 자동으로 해제됩니다. [캡처: 컨텍스트 칩이 켜진 입력창]

### 2.5 `@`로 파일 첨부

특정 파일을 대화에 포함할 때 사용합니다.

1. 입력창에 `@`를 입력하고 파일명 일부를 입력합니다.
2. 제안 목록(최대 25개)에서 파일을 선택합니다.
3. 여러 파일을 첨부하려면 반복합니다.

결과 확인: 첨부 목록에 파일이 표시되고, 전송 시 워크스페이스 상대 경로로 전달됩니다.

### 2.6 이미지 첨부

화면 캡처나 다이어그램을 함께 보낼 때 사용합니다. 이미지 첨부는 선택한 모델이 첨부를 지원할 때만 사용할 수 있습니다.

1. 다음 중 한 가지 방법으로 이미지를 추가합니다.
   - 입력창에 이미지를 붙여넣기
   - 입력창에 이미지 파일을 드래그 앤 드롭
   - 하단 **Image** 버튼으로 파일 선택 (여러 개 가능)
2. 요청을 입력하고 전송합니다.

결과 확인: 첨부 목록에 이미지가 표시됩니다. `image/*` MIME 타입만 허용됩니다. 크기 제한 [확인필요]

### 2.7 `/` 명령 실행

OpenCode에 정의된 명령이나 스킬을 호출할 때 사용합니다.

1. 입력창에 `/`를 입력합니다.
2. 제안 목록에서 명령을 고르고 필요하면 인수를 이어서 입력합니다.
3. `Enter`로 실행합니다.

내장 명령은 다음과 같습니다. 그 외 명령은 OpenCode 설정(`/command` 목록)에 따릅니다.

| 명령 | 동작 |
|---|---|
| `/new`, `/clear` | 새 채팅 시작 |
| `/help` | 입력 도움말 표시 |
| `/models`, `/model` | 모델 선택 상자 열기 |

엔진에 없는 명령을 입력하면 요청을 보내지 않고 "Unknown command" 안내를 표시합니다. 예전에는 이런 경우 엔진이 `Unexpected server error`를 돌려주었습니다.

### 2.8 도구 권한 승인

에이전트가 파일 편집이나 셸 명령을 실행하려 할 때 응답합니다.

1. 입력창 위에 권한 요청 카드가 표시되면 요청 종류와 패턴을 확인합니다.
2. 다음 중 하나를 선택합니다.
   - **Allow once**: 이번 요청만 허용
   - **Always allow**: 같은 패턴을 계속 허용
   - **Deny**: 거부

결과 확인: 카드가 사라지고 에이전트가 이어서 진행하거나 거부 결과를 반영합니다. [캡처: 권한 요청 카드]

### 2.9 권한 모드 설정

매번 승인하는 대신 기본 정책을 정할 때 사용합니다.

1. 입력창 하단 권한 모드 선택 상자에서 모드를 고릅니다.

| 모드 | 동작 |
|---|---|
| Manual | 편집·셸 명령 모두 승인 요청 (기본값) |
| Edit automatically | 파일 편집은 자동 허용, 나머지는 기본 정책 |
| Plan | 파일 편집 금지(읽기 전용), 셸 명령은 승인 요청 |
| Auto | 모든 도구 자동 허용 |

결과 확인: 선택 즉시 현재 세션에 적용되고 워크스페이스별로 기억됩니다. Auto 모드는 셸 명령까지 확인 없이 실행하므로 신뢰할 수 있는 작업에만 사용합니다.

### 2.10 에이전트 질문 응답

에이전트가 선택지를 제시하며 결정을 요청할 때 사용합니다.

1. 알림 영역 아래 질문 카드에서 선택지를 고릅니다. 복수 선택 질문은 여러 개를 고를 수 있습니다.
2. 자유 입력이 허용된 질문은 "Type your answer" 칸에 직접 입력합니다.
3. 제출합니다. 답하지 않으려면 거부 버튼을 선택합니다. [확인필요: 제출·거부 버튼 명칭]

## 3. 자주 하는 작업 (How-to)

### 선택한 코드만 리뷰받으려면

1. 편집기에서 코드 범위를 선택합니다.
2. 우클릭 후 **OpenCode: Add Selection to Chat**을 선택합니다.
3. 입력창에 "이 코드를 리뷰해 줘"를 입력하고 `Enter`를 누릅니다.

### 파일 수정을 일일이 승인하지 않으려면

1. 권한 모드를 **Edit automatically**로 바꿉니다.
2. 셸 명령은 계속 승인 카드로 표시되므로 필요 시 **Allow once**를 선택합니다.

### 코드를 건드리지 않고 분석만 시키려면

1. 권한 모드를 **Plan**으로 바꿉니다.
2. 요청을 보내면 편집 요청은 자동 거부되고 분석 결과만 표시됩니다.

### 엔진 로그를 확인하려면

1. 메뉴 보기 > 출력(Output)을 엽니다.
2. 채널 목록에서 **OpenCode Integrated**를 선택합니다.
3. 오류 알림의 **Show Logs** 버튼으로도 같은 채널을 열 수 있습니다.

### 컨텍스트 창이 얼마나 남았는지 보려면

1. 입력창 하단 토큰 표시에 마우스를 올립니다.
2. 현재 컨텍스트, 세션 누적, 컨텍스트 창 크기, 잔여량이 툴팁으로 표시됩니다. 80% 이상 사용하면 경고 색으로 바뀝니다.

컨텍스트 창 크기는 지금 선택한 모델 기준입니다. 모델이나 사고 강도를 바꾸면 곧바로 갱신되고, 툴팁에 어느 모델의 창인지 이름이 함께 나옵니다. 아직 답변이 없는 세션에서는 선택한 모델의 창 크기만 먼저 보여 줍니다. 직전 답변을 만든 모델과 지금 선택한 모델이 다르면 툴팁이 그 사실을 알려 줍니다. 모델 선택 상자에도 모델마다 창 크기가 함께 표시되어 바꾸기 전에 비교할 수 있습니다.

## 4. 제한 사항

- Windows x64 VSIX만 제공합니다. macOS·Linux·ARM 빌드는 별도 패키징이 필요합니다.
- 폴더나 워크스페이스를 열지 않으면 엔진이 시작되지 않습니다. 다중 루트 워크스페이스는 첫 번째 폴더만 사용합니다.
- 모델 제공자 자격 증명 등록 UI가 없습니다. OpenCode CLI 또는 `opencode.json`으로 구성합니다.
- 메시지 조회는 세션당 최근 200개까지입니다.
- 이미지는 `image/*` 타입만 첨부되며, 모델이 첨부를 지원해야 합니다.
- 링크는 `http`·`https`만 외부 브라우저로 열립니다.
- 폐쇄망·프록시 환경 동작 [확인필요]
